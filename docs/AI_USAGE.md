# AI 使用与验证记录｜把 AI 纳入可验证的产品研发闭环

更新：2026-09-29。本记录说明候选人与 AI 的实际分工、关键纠错和验证结果。文中的“我”指候选人对目标、口径和验收标准的选择；具体编码、取数检查、自动测试与浏览器操作由 Codex Agent 执行。不会把 Agent 自检写成候选人亲自完成的操作。

## 我的 AI-native 工作方式

我没有把题目当作“给模型一句话，让它推荐股票”的提示词演示，而是把 AI 放进一条可审计的产品研发链：**定义判断边界 → 让 Agent 探测真实能力并实现 → 用数据和程序反证假设 → 在浏览器里走通用户任务 → 把失败和限制反馈到下一轮实现**。每一步都有可检查的产物，模型输出不能跳过数据、规则或测试直接成为投资结论。

| 环节 | 我的决策与约束 | AI/工具承担的工作 | 交付的可检查结果 |
|---|---|---|---|
| 定义产品问题 | 将“经营改善、估值合理、走势稳定”拆成可编辑条件；默认解释必须显式告知用户 | Codex Agent把需求转成指标白名单、Schema、页面和测试任务 | 意图解释、条件编辑器和五条件预设 |
| 验证能力，而非猜接口 | 优先用真实扶摇数据；接口失败、字段缺失和口径差异不能用模拟值掩盖 | 读取已安装的`hithink-finance` Skill及CLI契约，执行真实请求，检查返回字段和原始值 | 300只成分的版本化快照、覆盖报告、原始字段证据 |
| 把概率输出限制在语义层 | LLM只能解释意图、假设、冲突与不支持项，不能选股或改写股票事实 | DeepSeek服务端返回JSON；TypeScript/Zod和程序规则验证其结构与语义 | 非预设条件解析；非法字段、虚构诉求、过期时间要求被拦截 |
| 让程序负责可重复的判断 | 比较符、波动率、PASS/FAIL/UNKNOWN、候选数量及条件变化必须确定性计算 | Agent实现纯函数筛选引擎与同快照差分，并编写边界测试 | 原始未舍入值判断、Near Miss与UNKNOWN分区、敏感性比较 |
| 用反馈闭环封住错误 | 通过原值复算、异常注入、浏览器主链路和发布检查验收；发现偏差再修正 | Agent执行Python独立复算、40项测试、Playwright及构建检查 | 测试说明、截图、83.88秒真实网页演示视频 |

这里的 AI-native 能力是**设计人机分工和证据回路**：让模型处理规则难以穷举的自然语言，让程序处理必须稳定一致的金融判断，让真实数据及其来源限制两者的结论。产品用户可以看到默认假设并修改它；开发者可以从候选股票追到原始字段和报告期。

## 实际使用的 AI 与工具

| 工具 | 本项目中的实际用途 | 明确边界 |
|---|---|---|
| Codex Agent | 阅读题目和Skill、规划与实现Next.js/TypeScript/Zod产品、写测试、运行命令、排查错误、做浏览器验收及整理文档 | 不能代替候选人作个人签核；生成的代码与结论须经数据和测试核对 |
| DeepSeek `deepseek-flash` | 产品运行时解释非预设自然语言，输出受约束的`NaturalLanguageIntent` JSON | 不接触金融API Key，不计算指标，不生成股票事实，不决定PASS/FAIL |
| `hithink-finance` Skill与CLI | 提供扶摇金融接口的操作说明和真实数据访问 | 是数据工具，不是投资判断模型；接口文档需以实际响应复验 |
| TypeScript/Zod、Python、Playwright | 分别校验契约与规则、独立复算金融数字、复走真实网页 | 它们是验证手段，不把合成测试数据冒充真实候选股票 |

完整预设短语由显式规则解释并标注“系统默认解释，可修改”；其他表达进入服务端DeepSeek。模型只能使用七项白名单指标，输出经过严格Schema和语义校验。筛选引擎只读固定快照；用户每次修改条件不会触发数百次金融API调用，也不会让模型重新计算股票指标。

## 候选人提出的纠错与取舍

以下是我在协作中明确提出、并要求 Agent 以实测而非话术解决的问题；具体操作与验收由 Agent 完成。

| 我指出的问题或提出的约束 | 形成的实现与验证 |
|---|---|
| 初版把“净利润同比”写得过于笼统；供应商实际字段是归母净利润同比 | 改为`parent_holder_net_profit_yoy_growth_ratio`，不再冒充合并净利润同比。抽取五只不同行业股票，用本期和上年同期利润表原值复算营收及归母净利润同比；10项最大差异为0.000000489个百分点 |
| 不能为了凑满覆盖率而填0、编造行情或丢掉取数失败的股票 | 快照保留完整300只成分；七项指标非空数为300/300/300/252/300/300/296。毛利率48只、波动率4只保留UNKNOWN；真实429失败被记录，续跑后恢复成功请求 |
| 先做真实快照、确定性筛选和证据，再接LLM | 主链路先用五条件预设跑通；随后接DeepSeek做非预设输入。模型只解释条件；股票入选与条件变化始终由程序计算 |
| 不能把UNKNOWN说成“差一点入选” | PASS/FAIL/UNKNOWN三态分开；Near Miss只包含数据完整的FAIL股票，逐项证据显示实际值、阈值、原始字段、来源、时间和报告期 |
| 产品必须可实际操作，不能停留在架构文档 | 条件可改阈值、改比较符、删除和新增；浏览器真实走通编辑PE上限、运行筛选、查看入选/排除原因及同快照变化 |

## Agent发现的问题，以及我是如何要求验证修正的

我要求每一项修正都留下可复现的规则、数据或测试，而不是接受“模型看起来理解了”的演示效果。

| 发现的偏差 | 修正及验证证据 |
|---|---|
| 60个价格只能产生59个日收益率 | 使用61个连续交易日收盘价计算60个收益率，按样本标准差乘`sqrt(252)`年化；TypeScript与Python独立复算一致 |
| 把`null`当作失败，或用一个时间字段表示所有金融数据 | 保留三态判断；区分`as_of`、`retrieved_at`和`report_period`，供应商未提供的精确时点标为未知 |
| 预设过宽、模型添加用户未说的限制 | 预设只匹配完整表达；不支持项必须能对应用户原话，模型虚构字段或诉求时拒绝解析 |
| “今天”或指定旧报告期可能被模型简化成普通PE条件 | 增加独立时间约束检查；与固定快照不符时要求澄清，筛选API也拒绝执行。ISO日期、年报简写及“不要求今天”等边界已回归测试 |
| 同日刷新可能命中错误缓存或覆盖旧证据 | 缓存绑定请求参数和哈希；原始响应按内容保存为不可变引用。旧快照604份、首轮新快照599份、续跑快照604份引用均无缺失或哈希不匹配 |
| 供应商真实429没有进入预期重试路径 | 将实际错误码纳入有限退避，失败照实入库；续跑补齐5个失败请求。退避期间供应商恢复仅做过故障注入测试，不宣称已在真实429期间验证成功 |

## 验证结果与我保留的判断边界

- **数据**：最新真实快照`snap-2026-09-29-2026-2-4f5db3320b0d`包含沪深300全部300只，质量为`partial`，七指标覆盖见上文；原始响应和哈希留在Git忽略的本地验证目录。五行业原值复算、单只波动率双语言复算见[数据验证记录](DATA_VERIFICATION.md)。
- **模型**：真实DeepSeek将“营收同比至少8%、PB不高于2倍”解析为两条件，网页筛出62只PASS、238只FAIL、0只UNKNOWN；“保证明天涨停”和当前不支持的行业排除请求被标记并要求澄清。这是样本验证，不能外推为任意中文表达都正确。
- **工程与体验**：lint、typecheck、40项自动测试、build、release检查及公网Playwright主链路通过。五条件把PE上限改为35时，网页显示300只中21 PASS、278 FAIL、1 UNKNOWN；PASS/FAIL/UNKNOWN证据和同快照比较都已浏览器验收。细项见[测试说明](TEST_PLAN.md)。
- **安全与合规**：产品运行时的DeepSeek Key保存在服务端Secret，金融Key仅供本机维护脚本从用户级凭据读取；Git仓库不跟踪真实快照、原始响应或密钥。产品不提供收益承诺、买卖建议或自动交易。供应商针对规范化数据公开展示的独立许可**尚未确认**，见[公开材料核查](DATA_LICENSE_REVIEW.md)。

这份记录说明的是实际完成的协作和验证，不把工具自检包装成候选人亲自操作，也不把有限测试说成全面质量保证。最终产品：[公开网页](https://stock-intent.vercel.app)；[源代码仓库](https://github.com/WESSELL0/stock-intent)。
